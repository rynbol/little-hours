# Little Hours: timer, session, and accessible interface research

Checked **2026-09-25, America/Los_Angeles**. Repository snapshot: `05e742603075595e180c4639ac4c1b7236d843de`, origin/main. This is a source audit and primary-documentation review, not a hands-on comparison or an accessibility conformance certification. No application code was changed. Effort estimates: **S** = a contained change; **M** = several interacting components or a persisted-state migration; **L** = a product subsystem. They are relative, not delivery commitments.

## Decision

Keep the existing vanilla JavaScript/Vite/Babylon architecture and deadline-based timer. The most valuable timer work is explicit session semantics, a real optional break timer, understandable completion feedback, and a small local task/history experience. A component framework will not supply those product decisions. Native HTML, a restrained SVG progress treatment, and small local UI modules are the first choice. Trial Floating UI only where positioning becomes difficult; Lucide is a reasonable selective icon source. Defer XState and animation engines until there is demonstrated complexity that justifies them.

The product vision makes the room, study station, companion, and honest local presence central. It also promises rewards for completed sessions, not abandoned ones. Timer settings should remain subordinate to that room. No reference below supplies artwork, furniture, character designs, or permission to copy another product. All 3D assets remain deliberately modeled geometry, consistent with `AGENTS.md`.

## What is actually implemented

| Functional block | Current evidence | Assessment and next step |
|---|---|---|
| Focus duration | `src/main.js:121`, `src/state.js:7,39–54` | Only 25/50/90 minutes are offered **and accepted on restore/history restore**. Custom duration is a schema change, not merely another input. No scientific claim about a universally ideal duration is warranted. |
| Start, pause, resume | `src/session.js:25–32`; `src/main.js:445–493` | Start writes a wall-clock deadline; pause freezes the remainder; resume preserves it. Labels change with state. Keep these semantics. |
| Background/sleep recovery | `src/session.js:5–7`; `src/main.js:483–485,1016–1028` | Remaining time is deadline minus current time, not a decremented counter. Storage/visibility refresh and a 500 ms poll already recover delayed execution. A worker timer is not needed to fix ordinary interval drift. |
| Reset and duration changes | `src/main.js:495–505` | Reset abandons an unfinished session; focus returns to Start when Reset hides. Picking the selected duration preserves paused progress. Picking a **different** duration while paused replaces that session without a separate explanation. Running sessions disable duration buttons. |
| Breaks | `src/session.js:10–22` | Paused focus is presented as “break.” Completion remains in break presence for 15 minutes, then displays a fresh focus duration. **This is status expiry, not a running break timer.** There are no short/long break durations or cycles. |
| Completion/reward | `src/state.js:62–70,89–108`; `src/main.js:222–232` | Completion settles before each mutation, appends a date/minutes record and credits coins. The room/pet reacts and a toast appears. No dedicated audible completion alert or browser notification is implemented in this path. |
| Current task | `src/main.js:119–120,507–510`; `src/state.js:25` | One text field, capped at 180 characters. Each input synchronously saves the whole state. There is no task collection, done status, estimate, or session task snapshot. |
| History | `src/state.js:51–54,67–68`; `src/main.js:450–452` | Only `{date, minutes}` records; UI derives today's completed minutes. Retention is **365 records, not 365 days**. There is no visible journal/list, timestamp, task association, or export. |
| Date accounting | `src/state.js:14–17,64–67` | A session reopened tomorrow is assigned to the local date of its deadline. It is not assigned to reopening time. Local timezone is evaluated at settlement; original timezone is not stored. |
| Persistence | `src/state.js:77–108`; `src/main.js:228–230,1025–1028` | Corrupt saves normalize safely; failed writes preserve the current visit; a warning is shown; stale tabs reread storage before mutation. These are genuine mitigations. They do not make read-modify-write transactions atomic across simultaneously executing tabs. |
| Accessible output | `src/main.js:91–92,121,132,460,469–474` | Timer role; live local-presence and companion statuses; a toast status; accessible button labels. Updating `aria-label` to “24:59 remaining” is less explicit than minutes/seconds. Do not make every tick a spoken announcement. |
| Sound | `src/main.js:988–1013` | Gesture-started synthetic rain through Web Audio, gain fades, volume range, and context suspension when switched off. Sound/volume preferences are not in persisted state. This is ambient audio, not a completion cue. |
| Responsive surface | `src/style.css:278–389`; `src/main.js:565–578` | Tablet/mobile layouts, collapsible focus dock, reduced-motion-aware scrolling, coarse-pointer enlargements, native range input. The dock remains a local in-page surface, not a native notch app. |

`src/session.test.js` already covers throttled/sleeping time, pause/resume, deadline-boundary pause intent, sequential multi-store completion, reopening on another day, malformed saves, blocked writes, and backwards clock clamping. These should be extended, not replaced by tests that merely duplicate rendering code. This research read tests; it did not execute them.

## Timer components and lifecycle to build

**Adopt: an explicit lifecycle model, M.** Separate internal session state from presence. Suggested state distinctions are ready, focusing, paused focus, completed, and timed break; presence may still deliberately map paused focus to “On a break,” following product vision. Store a session ID, kind, configured duration, deadline/remainder, start/completion timestamps, and optional task snapshot. Keep deadline arithmetic in `session.js`, settlement/reward rules in `state.js`, and rendering in a small timer-view module extracted from `main.js`. The 3D companion consumes a derived intent, never becomes the timer's source of truth.

Pausing currently earns no immediate coins, but resuming and eventually completing earns the full configured duration. That is a coherent reading of the vision; document it before adding metrics. Abandoned work could be visible as optional elapsed effort without awarding completion coins. Never silently change the existing economy when adding a task list or break timer.

**Adopt: optional timed breaks, M.** Offer a simple “Take a break” action at completion, with short/long break settings in a secondary panel. User-selectable defaults such as 5/15 minutes are product choices, not health advice. Break time earns no focus coins. Make skip/end break explicit and avoid starting another focus block automatically by default. Automatic cycling, long-break cadence, and auto-start should be separate preferences only after basic transitions work. Acceptance: reload during break, finish in a hidden tab, skip break, pause then resume focus, and start a new focus after completion all preserve kind and avoid extra rewards. Existing 15-minute presence expiry requires a migration decision; do not reinterpret legacy completed saves as newly running breaks.

**Adopt: duration controls with deliberate loss handling, M.** Preserve 25/50/90 as convenient presets. If custom durations are justified, use a labeled native numeric input with explicit bounds and a unit, not a draggable clock face. Validate at the UI **and** restore boundaries; update reward calculation, history validation, tests, and display together. Explain that changing a partially completed focus starts fresh; offer a reversible abandoned-session recovery where feasible instead of a heavy confirmation on every setting change. Acceptance: selected preset is a no-op, another preset cannot erase paused work without clear intent, invalid values never yield NaN/negative time, and old saves still load.

**Adopt: a readable, noninteractive progress dial, S.** Native `<progress>` with a label is sufficient; an original SVG ring is a visual alternative. Keep one accessible time output and hide purely decorative duplicate geometry. Express elapsed fraction consistently, reset on a new session, freeze while paused, and distinguish break by words and icon as well as color. Do not expose an output-only ring as a slider. The timer role has implicit `aria-live="off"`, which suits a changing countdown; put start/pause/completion summaries in a separate polite status. Provide spoken text such as “24 minutes, 59 seconds remaining.” [MDN timer role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/timer_role)

**Adopt: completion panel and optional chime, S/M.** A 4.2-second toast (`main.js:136–142`) is too ephemeral to be the sole outcome surface. Keep a calm completed state with earned coins and actions for break/new session. Add independent completion-sound enable/volume settings and a preview initiated by a user gesture. Reuse Web Audio for a short original cue; no audio library is needed. Keep rain settings independent. Acceptance: no sound on initial load, no duplicate chime from render ticks, denied/suspended audio fails quietly, and long-overdue sessions recovered on opening do not trigger a surprising alarm storm.

**Trial: browser notifications, M.** Useful when studying outside the visible tab, but do not promise alarms after the browser is terminated or a laptop sleeps. Permission must follow an explicit user action; secure contexts are required in relevant browsers, and mobile notification construction differs from desktop. A service worker is a delivery surface, not a reliable local alarm clock by itself. Show permission state, use generic text by default rather than putting private task names on lock screens, and deduplicate by session ID. [MDN Notifications guide](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API)

**Defer: wake lock, S.** It may help a user who deliberately wants the room visible, but should be opt-in because it opposes energy saving. Feature-detect; release on completion/disable; handle automatic release and re-acquisition on visibility. It does not solve background alarms. [MDN Screen Wake Lock](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API)

**Adopt: explicit accounting policy, M.** Preserve “credit to completion date” unless the product deliberately chooses a different journal rule. Store completion timestamp and an IANA timezone/date snapshot when created/settled so subsequent travel cannot rewrite history. Test midnight, daylight-saving transitions, reopening days later, and manual clock jumps. Current backwards clamp prevents time exceeding configured duration, but cannot determine whether a wall-clock jump represents real elapsed work. Use monotonic time for within-page diagnostics if helpful while retaining persisted wall deadlines for reload recovery; do not present any local timer as tamper-proof.

For multiple tabs, current tests demonstrate sequential settlement, not simultaneous interleaving. Before richer history or notifications, trial a named Web Lock around save/settlement plus stable IDs, with an explicit fallback. This requires an asynchronous store seam. Locks coordinate same-origin tabs/workers; they are not cross-device synchronization. [MDN Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)

## Tasks and history without a productivity dashboard takeover

**Adopt: a small native task list, M.** Start with a current-task field plus optional “Up next” list, native checkboxes, and explicit select/rename/delete controls. Retain an empty-state path that starts focus without a task. Do not require estimates, projects, labels, recurring tasks, or external integrations to begin. Use an ordered list if order is meaningful; add up/down buttons before drag-and-drop. Capture task ID and text snapshot on session start so renaming a task cannot rewrite completed work. If switching task mid-session is allowed, define whether history records the starting task or segments; choose one simple policy initially.

Move task draft updates away from a full state clone/save on every keystroke, but preserve text on blur/page lifecycle and during IME composition. Do not let cross-tab refresh unexpectedly overwrite active editing. Session controls should remain responsive with the largest supported house save. Acceptance: keyboard-only task creation/selection/completion, long text wrapping, literal rendering of user markup, persistence failure feedback, and migration of the existing single task.

**Adopt: session history list and accessible weekly summary, M.** A disclosure below the timer or a secondary journal panel should show date, completed minutes, and task snapshot when known. A seven-day CSS bar chart or compact SVG is enough for the initial summary, backed by an HTML table/list with exact numbers. Label empty days; do not turn missed days into failure states. Keep completed focus distinct from paused/abandoned effort and breaks. Give retention and clear/export controls understandable wording. Local JSON export can preserve full fidelity; add CSV only when useful, with spreadsheet-formula escaping for task names.

**Defer: Chart.js and calendar libraries.** There is no current interactive analytics need that requires a chart runtime or complex date picker. An accessible table and seven original bars avoid a canvas-only access problem and another rendering subsystem. Revisit only for multi-series zoom/filter interaction and a real data volume. Native `Intl.DateTimeFormat` and local date helpers suffice for display; a timezone/date library becomes justified only when requirements exceed those utilities. Do not claim 365 days of history while `slice(-365)` retains sessions.

## Accessibility and interaction details that matter

Native `<dialog>.showModal()` provides platform modal behavior and background inertness; still supply a useful accessible name, appropriate initial focus, close action, and return focus. Use it for genuinely interrupting decisions. Keep the existing ordinary settings panels nonmodal when room interaction should remain available. Avoid trapping focus in every small popover. [MDN dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog)

For actual tab panels, implement selected state, controlled panels and arrow-key navigation from the APG pattern. A row of mutually exclusive duration settings is not automatically a tab interface. Keep the native range for volume; a custom dial requires substantial keyboard/value semantics and mobile assistive-technology testing. [WAI tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/), [WAI slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)

Coarse-pointer rules currently enlarge several controls, but omit duration buttons and the start button; icon buttons become 40 px, and volume remains 20 px tall (`style.css:174,381–387`). This is not a measured WCAG failure: WCAG 2.2 AA target size includes 24 CSS px and spacing exceptions. Use a consistent 44 px ergonomic target where feasible, including hybrid touch laptops, rather than relying solely on the primary pointer media query. Preserve scroll-vs-room-drag behavior (`touch-action: pan-y`, line 47) and test actual touch gestures. [WCAG target-size explanation](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

Focus styling exists (`style.css:12`) and reset/panel close restore focus. The canvas removes its focus outline (`style.css:48`); audit whether it is keyboard-focusable and give it a meaningful visible state if so. Measure text, muted text, input boundaries and focus indicators against the final composited backgrounds. No source-only contrast certification is possible. Check 200%/400% zoom, 320 CSS px width, landscape phone, on-screen keyboard, safe areas and long translated labels. Keep the timer accessible when the room is tall and avoid sticky controls covering text.

Reduced-motion CSS already disables transitions/animations globally (`style.css:389`). Later active/hover rules still apply transforms (`style.css:529–531`): they may snap rather than animate, so inspect comfort rather than claiming motion is entirely absent. Prefer no continuous pulsing progress or bouncing digits. Announce only meaningful phase changes; multiple existing live regions can overlap, so centralize timer announcements and keep decorative companion chatter optional.

**Shortcuts: trial, S.** Native Enter/Space activation is the baseline. If adding a shortcut to start/pause, make it discoverable and optionally disabled; never capture Space while the user types, uses a range, composes text, or navigates another control. Reuse the existing typing/modifier guard pattern (`main.js:971–985`). A command palette library is unnecessary for this action count.

## Typography and product references

Keep the current DM Sans/Manrope/Georgia direction. The timer already uses tabular numerals (`style.css:157`), which avoids width jitter. The external Google Fonts stylesheet is nonblocking in `index.html:10–13`, so font failure does not block first paint. **Trial self-hosted WOFF2, S** for predictable offline/privacy behavior, using either direct files or Fontsource packages. Fontsource distributes self-hostable npm fonts; its tooling license does not replace each font's license. DM Sans and Manrope carry SIL Open Font License files in Google's font repository. Retain those notices and compare actual transfer size and layout shift before adopting; two families may be unnecessary. [Fontsource repository](https://github.com/fontsource/fontsource), [DM Sans license](https://github.com/google/fonts/blob/main/ofl/dmsans/OFL.txt), [Manrope license](https://github.com/google/fonts/blob/main/ofl/manrope/OFL.txt)

Three references are useful for specific questions, not wholesale copying:

- **Pomofocus:** its official page connects task selection, estimates, focus/break cycles, and reports. Borrow clarity of the next action; defer its fuller planning/reporting scope. The page describes customary timing, not evidence that a duration is optimal. [Official site](https://pomofocus.io/)
- **Spirit City: Lofi Sessions:** the developer's Steam listing combines a customizable room, companion discovery, timer, tasks and earned progression. It is the closest conceptual reference for making productivity tools subordinate to a cozy place. Study how the room and tools coexist; do not copy assets, XP balance, UI or music. [Developer listing](https://store.steampowered.com/app/2113850/Spirit_City_Lofi_Sessions/)
- **LifeAt:** the official site lists virtual spaces, timer, sound, coworking and planning tools. It helps identify the breadth Little Hours could grow into—and why accounts, calendars and collaboration should remain deferred until solo focus is dependable. [Official site](https://lifeat.io/)

## Recommended acceptance sequence

1. **First: lifecycle clarity and completion, M.** Preserve existing deadline tests; add break-kind and transition tests, human-readable timer labels, one completion announcement, stable session IDs, and a persistent completed state. Confirm local presence never implies a friends connection.
2. **Second: input/accessibility pass, S/M.** Keyboard and real touch checks for every timer action; screen-reader checks with ticking silenced and transitions announced; zoom/reflow, reduced motion, contrast measurements, focus restoration, and font-blocked loading. Keep Babylon's render budget unaffected.
3. **Third: local tasks/history, M.** Migrate the old single task, preserve old date/minutes records honestly, add accessible history and seven-day summary, define retention, and verify storage failures and concurrent writes. Recheck reward idempotence at midnight and on reload.
4. **Then: optional alerts and narrow library trials.** Test the same scenarios with muted/denied audio, notification denial, hidden tabs, sleeping devices and multiple tabs. Keep a dependency only if it resolves a demonstrated need better than the native baseline. More features should not make starting a quiet session slower.
